# 全栈 AI 智能体平台 —— 需求文档

## 1. 项目概述

### 1.1 项目背景

本项目旨在构建一个企业级全栈 AI 智能体（AI Agent）平台，基于 LangGraph 实现 ReAct 推理循环，以工具形式封装 RAG 能力供模型自主决策调用，配套三层记忆架构实现跨会话个性化体验，并通过流式对话与 Agent 执行过程可视化提供良好的用户交互体验。

### 1.2 项目目标

- 构建基于 LangGraph 的 ReAct 推理引擎，支持检查点持久化与执行恢复
- 实现双轨记忆系统（短期记忆 + 长期记忆），支持会话中断恢复与跨会话个性化
- 提供 RESTful API 与 SSE 流式接口，实现 Agent 思考过程与工具调用进度的实时推送
- 构建 Vue 3 前端，支持流式对话、工具调用卡片可视化与历史会话管理
- 接入 LangSmith 实现全链路可观测性，监控 Token 消耗与调用耗时

### 1.3 目标用户

- 终端用户：通过 Web 界面与 AI 智能体进行对话交互
- 开发者：通过 API 集成智能体能力到其他应用
- 运维人员：通过可观测性工具监控系统运行状态与成本

## 3. 功能需求

### 3.1 ReAct 推理引擎

#### 3.1.1 功能描述

基于 LangGraph 实现 ReAct（Reasoning + Acting）推理循环，使智能体能够按照“思考 → 行动 → 观察”的循环模式进行推理与工具调用。

#### 3.1.2 核心功能

| 编号     | 功能点         | 描述                                                         |
| :------- | :------------- | :----------------------------------------------------------- |
| REACT-01 | ReAct 循环引擎 | 基于 LangGraph StateGraph 构建 ReAct 推理图，包含 Agent 节点（推理决策）与 Tools 节点（工具执行）的循环编排 |
| REACT-02 | 检查点持久化   | 使用 PostgresSaver 作为检查点存储后端，在图每次节点执行后自动保存状态快照 |
| REACT-03 | 执行恢复       | 通过 thread_id 恢复中断的会话，支持从任意检查点恢复执行      |
| REACT-04 | RAG 工具封装   | 将 RAG 检索能力封装为 LangChain Tool，由模型在 ReAct 循环中自主决策调用 |
| REACT-05 | 提示注入防御   | 在 System Prompt 中硬编码不可绕过的授权与安全指令，对用户输入进行过滤与校验 |
| REACT-06 | 回归测试       | 建立工具调用与推理路径的回归测试套件，确保系统迭代不破坏核心逻辑 |

#### 3.1.3 技术实现要点

python

```
# 示例：ReAct Agent 编译
from langgraph.prebuilt import create_react_agent
from langgraph.checkpoint.postgres import PostgresSaver

checkpointer = PostgresSaver.from_conn_string(DB_URI)
checkpointer.setup()  # 首次运行创建表[reference:13]

agent = create_react_agent(
    model=llm,
    tools=[rag_tool, memory_tools, ...],
    checkpointer=checkpointer
)

# 执行时传入 thread_id
result = await agent.ainvoke(
    {"messages": [{"role": "user", "content": user_input}]},
    {"configurable": {"thread_id": thread_id}}
)
```



> **注意**：`thread_id` 长度需保持在 255 个字符以内。

### 3.2 双轨记忆系统

#### 3.2.1 功能描述

LangGraph 的持久化层通过 Checkpointers 提供短期记忆，通过 Stores 提供长期记忆。本项目实现三层记忆架构：thread-level 短期记忆、user-level 会话级记忆、跨会话长期记忆。

#### 3.2.2 记忆架构

| 记忆层级                      | 存储机制                   | 作用域                          | 用途                               |
| :---------------------------- | :------------------------- | :------------------------------ | :--------------------------------- |
| **短期记忆（Thread-level）**  | PostgresSaver（检查点）    | 单线程（thread_id）             | 多轮对话上下文、会话状态、执行断点 |
| **会话级记忆（User-level）**  | PostgresStore（namespace） | 用户级（user_id 下所有 thread） | 用户在当前会话周期内的偏好与状态   |
| **长期记忆（Cross-session）** | PostgresStore + 向量检索   | 跨会话（user_id 全局）          | 用户画像、事实记忆、偏好持久化     |

#### 3.2.3 核心功能

| 编号   | 功能点             | 描述                                                         |
| :----- | :----------------- | :----------------------------------------------------------- |
| MEM-01 | 短期记忆持久化     | 基于 PostgresSaver 自动保存每个 thread 的图状态与消息历史    |
| MEM-02 | 会话中断恢复       | 通过 thread_id 恢复中断的对话，保持上下文连贯性              |
| MEM-03 | 跨会话长期记忆     | 基于 PostgresStore 以 `namespace` + `key` 存储用户级数据，跨 thread 共享 |
| MEM-04 | 语义检索           | 集成 pgvector 支持对长期记忆的向量语义检索                   |
| MEM-05 | Agent 主动读写记忆 | 通过自定义工具（如 `save_memory`、`recall_memory`）让 Agent 主动读写长期记忆 |
| MEM-06 | 检查点清理策略     | 定期清理过期检查点，防止无限增长                             |

#### 3.2.4 技术实现要点

python

```
# 示例：PostgresStore 配置
from langgraph.store.postgres import PostgresStore
from langgraph.checkpoint.postgres import PostgresSaver

# 长期记忆存储（支持向量检索）
store = PostgresStore.from_conn_string(
    DB_URI,
    index={
        "dims": 1536,  # 向量维度
        "embed": embedding_model,
        "fields": ["text"]  # 需要 embedding 的字段
    }
)
store.setup()

# 编译图时同时传入 checkpointer 和 store
graph = builder.compile(checkpointer=checkpointer, store=store)

# Agent 节点中读写记忆
def agent_node(state, config, *, store: BaseStore):
    user_id = config["configurable"]["user_id"]
    ns = ("memories", user_id)
    # 语义检索
    hits = store.search(ns, query=state["messages"][-1].content, limit=5)
    # 写入记忆
    store.put(ns, memory_id, {"text": "用户偏好..."})
```



> **注意**：PostgresSaver 与 PostgresStore 数据隔离、能力互补，分别用于短期会话状态与长期用户记忆。

## 5. 数据模型

### 5.1 核心实体

python

```
# 会话（Thread）
class Thread:
    id: str           # thread_id，全局唯一，≤255字符[reference:51]
    user_id: str      # 所属用户
    created_at: datetime
    updated_at: datetime
    title: str        # 会话标题
    metadata: dict    # 元数据

# 消息（Message）
class Message:
    id: str
    thread_id: str    # 所属会话
    role: str         # user / assistant / tool
    content: str      # 消息内容
    tool_calls: list  # 工具调用记录（如有）
    created_at: datetime

# 用户记忆（Memory）
class Memory:
    id: str
    user_id: str      # 所属用户
    namespace: str    # 记忆命名空间
    key: str          # 记忆键
    value: dict       # 记忆内容
    embedding: list   # 向量（用于语义检索）[reference:52]
    created_at: datetime
    updated_at: datetime
```



### 5.2 数据库表结构（PostgreSQL）

**LangGraph PostgresSaver 自动创建的表**：

- `checkpoints` — 检查点快照
- `checkpoint_writes` — 增量写入
- `checkpoint_blobs` — 大对象存储
- `checkpoint_migrations` — 迁移版本

**PostgresStore 自动创建的表**：

- `store` — 键值存储（含向量索引，如启用 pgvector）

**应用层表**：

- `threads` — 会话元数据
- `messages` — 消息记录
- `users` — 用户信息

### 7.2 版本兼容性说明

1. **LangGraph v1.0 迁移**：LangGraph v1.0 与 v0.2.x 保持高度向后兼容，核心 Graph API 与执行模型不变。升级时需注意 Python 版本要求（≥3.10）。
2. **PostgresSaver 与 PostgresStore**：两者均需调用 `setup()` 方法初始化数据库表。PostgresStore 自 v1.0 起支持 pgvector 向量检索。
3. **LangSmith 集成**：LangSmith 与 LangGraph 版本需保持兼容，建议使用 LangGraph 0.2.50+ 与 LangSmith 0.1.0+。
4. **Python 版本**：所有 LangChain 包自 v1.0 起要求 Python 3.10 或更高版本。

### 7.3 升级策略

- **开发环境**：使用最新稳定版本，定期更新依赖
- **生产环境**：使用固定版本（pinned），在预发布环境完成兼容性测试后升级
- **重大版本升级**（如 LangGraph v0.2 → v1.0）：先在开发分支验证，通过回归测试后再合并
